# SELLAYER — 출시 로드맵 / 검증 계획

> **문서 ID:** SL-PLAN-001 · v0.1 · 2026-10-15  
> **성격:** 목표 단계와 승인 관문. 날짜/투입 인원/공식 플랫폼 승인은 아직 확정되지 않음.  
> **기준 문서:** [PRD](./PRD.md), [채널 연동](./CHANNEL_INTEGRATIONS.md)

## 1. 제품 전략

**독립 웹 SaaS를 먼저 완성하고, 카페24 앱스토어로 초기 유통 → 네이버 커머스솔루션마켓으로 확장한다.**

- 초기 상품군: 주얼리/패션 액세서리에서 원형 보존 품질을 입증한 뒤 확장.
- 경쟁 우위: `Product Fidelity` + `진짜 편집 가능한 PDP` + `승인 기반 멀티채널 게시`.
- AI 비용을 통제하기 위해 무제한 생성 아닌 **구독 + 크레딧 모델**을 기본 가설로 둔다.
- 요구사항에 적힌 성능 수치는 실측 전 목표일 뿐 고객 대상 보장 문구로 사용하지 않는다.

## 3. Discovery / PoC에서 가장 먼저 검증할 질문

### PoC-A: AI 이미지 상품 보존

- 주얼리 중심으로 다양한 품목·색상·형태의 **권리 확보된 상품**을 테스트.
- 참조 이미지 구성: 정면/측면/디테일, 컬러 옵션, 소재/특징 Lock.
- 컷 유형: 모델 착용샷, 단독컷, 디테일, 라이프스타일.
- 평가: 제품 비율·장식 위치·잠금 방식·보석 개수·광택/색상·모델 비율/손가락 수·텍스트 왜곡.
- 기록: 요청당 출력 성공률, 초안 승인률, 평균 재생성 횟수, 실제 생성 비용, p50/p95 지연.
- Go/No-Go: **치명적인 형태 변형을 통제하지 못하면 공개 출시 보류**. 수작업 합성/상품 레이어 합성 대안 검토.

### PoC-B: 편집/내보내기 동일성

- JSON 블록 문서로 상세페이지 1개 생성, 요소 이동·편집·복제, 자동 저장, 버전 복원.
- 동일 문서를 웹 미리보기와 PNG/긴 이미지/HTML로 출력해 레이아웃·텍스트·폰트·순서 비교.
- 채널별 크기/태그/이미지 URL 제약을 렌더러 계층에서 흡수 가능한지 검증.
- Go/No-Go: **수정한 내용이 실제 게시 결과에 재현되지 않으면 편집 UX 재설계**.

### PoC-C: 비용/대기열

- 이미지 10~30장 규모 파일럿으로 원본/참조 이미지 입력 원가, 품질별 요금, 재생성률 측정.
- 사용자 일일 100장 요청에 대한 큐 설계, 동시성 제한, 비용 상한 및 공급자 rate limit 대응 설계.
- 예상 크레딧과 실제 정산 차이를 분석하고 요금제 결정 전 가정 공개.

## 5. 배포 전략 (계획, 아직 구현되지 않음)

- 소스: `jskjw157/SELLAYER` GitHub, `main` 프로덕션 보호 + PR 리뷰 + 필수 CI.
- 서버: **Hostinger VPS Ubuntu 24.04**. Docker Compose / Reverse Proxy / HTTPS.
- `pull_request`: Lint, typecheck, unit tests, contract tests, 에디터 snapshot tests, 취약 의존성/시크릿 검사.
- `main` merge: 빌드된 이미지(커밋 SHA 태그) → Registry 배포 → 승인된 환경에 배포. 빌드/배포 권한 최소화.
- 프로덕션: GitHub Environment 승인 게이트, 제한된 SSH Deploy 계정, Secrets는 서버 또는 GitHub Secrets에 저장.
- 런타임: API/Web, Worker, PostgreSQL, Redis, Reverse Proxy, Object Storage 연동.
- 배포 전 DB 백업/마이그레이션, 배포 후 Healthcheck 및 smoke test, 실패 시 이미지 버전 롤백.
- 데이터 백업/복구, 로그 보존, HTTPS 도메인, SMTP/알림, 외부 API 키 확보는 제품 공개 전 필수.
- **PRD 단계에서는 workflow, Dockerfile, VPS 설정 변경을 수행하지 않음**. 별도 기술설계 및 보안 검토 뒤 구현.

## 7. 결정이 필요한 항목

1. B2B 요금 체계/월 포함 크레딧/생성 실패 환불 기준.
2. MVP 편집기 수준 (자유 위치 vs 강한 템플릿 기반).
3. 제품 형태가 달라졌을 때 자동 reject 임계치와 사람 승인 정책.
4. Cafe24 앱스토어/네이버 솔루션마켓 출시의 법인·사업자·정산 요건.
5. 원본 이미지 및 생성 이미지의 삭제/보관 기간과 백업 정책.
6. AI 제공사/모델 선정 및 고품질 컷당 목표 원가.
7. 최초 템플릿(주얼리만 먼저 vs 범용 상품 바로 지원).
