## 0. 문서 활용 원칙

- 이 문서는 **제품의 무엇과 왜**를 정의한다. 구현 세부 구조, DB 스키마, API 계약, UX 와이어프레임, 인프라 설정은 기술설계 단계에서 별도로 확정한다.
- `MUST`는 해당 출시 단계의 필수 요구사항, `SHOULD`는 우선 구현 요구, `MAY`는 선택 사항이다.
- **가정/목표 수치와 확정 사실을 구분**한다. 수치와 기술 선택은 검증 후 조정할 수 있다.
- 고객이 입력하지 않은 소재·효능·원산지·치수·KC 인증 등 **사실성 요구 정보는 AI가 추측해 게시하지 않는다.**
- **AI 생성 이미지의 상품 동일성은 100% 보장하지 않는다.** 검사·재생성·승인 절차를 제품 기능으로 설계한다.

## 1. Executive Summary

**SELLAYER**는 판매자가 원본 상품 이미지와 최소한의 상품 정보를 업로드하면 AI가 상품 단독컷, 가상 모델 착용샷, 라이프스타일 컷, 상세페이지 초안을 생성하고, **Figma/Canva 계열의 웹 편집 UX**로 개별 요소를 수정한 다음 카페24와 스마트스토어 등 판매 채널에 맞게 내보내거나 게시할 수 있는 **독립 멀티채널 SaaS**이다.

### 1.1 핵심 가치 제안

1. **One product → complete content:** 원본 상품 이미지에서 판매용 콘텐츠 패키지까지 한 흐름으로 제작.
2. **Product fidelity first:** 디자인, 형태, 소재감, 금속 색상, 장식 위치 등 검증해야 할 제품 특징을 명시적으로 보존·비교.
3. **Truly editable pages:** 납작한 한 장 이미지가 아니라 텍스트·이미지·섹션·레이어를 다시 편집할 수 있는 문서.
4. **Create once, publish anywhere:** 원본 프로젝트를 유지한 채 채널별 규격에 맞춰 게시.
5. **Cost-controlled batch generation:** 이미지 생성량·품질·재시도·예산을 사용자와 운영자가 통제.

### 1.2 초기 집중 시장

- **초기 카테고리:** 주얼리·패션 액세서리 (귀걸이, 목걸이, 반지, 팔찌, 헤어 액세서리).
- **확장 카테고리:** 의류, 가방, 신발, 뷰티/라이프스타일.
- **고객 채널:** 1차 독립 웹 서비스, 2차 카페24 앱스토어, 3차 네이버 커머스솔루션마켓.
- **파일럿:** 사용 권한이 확인된 실제 브랜드 상품 사진으로 제품 동일성 테스트. HAAR는 내부 검증 후보일 뿐 고객 데이터 기본값이 아니다.

## 2. 문제 정의와 사용자

### 2.1 문제

소규모 이커머스 셀러는 상품 사진 촬영, 가상 모델 섭외, 보정, 상세페이지 편집, 스토어 등록을 여러 서비스에서 반복한다. AI 이미지 도구만 쓰면 **제품 형태 변형**과 **재작업/재생성 비용**이 발생하고, 이미지 파일로만 내보내는 툴은 문구·배치 수정과 채널 업데이트가 비효율적이다.

### 2.2 주요 페르소나

| Persona | 핵심 작업 | 가장 큰 불편 | 성공 기준 |
|---|---|---|---|
| P1. 1인 셀러 | 신상품 1~5개 빠르게 등록 | 촬영 및 디자인 외주 비용 | 원본 업로드 → 승인 가능한 상세페이지 생성 |
| P2. 브랜드 운영자 | 일관된 모델과 무드 유지 | 모델·구도·상품 형태의 일관성 | 브랜드 프리셋 재사용, 컬러 옵션 별도 관리 |
| P3. 상세페이지 제작 대행자 | 여러 브랜드의 결과물 납품 | 반복 편집·수정 요청 | 레이어 수정, 버전 복원, 고해상도 출력 |
| P4. 쇼핑몰 운영 담당 | 카페24/스마트스토어 업데이트 | 이중 등록 및 형식 차이 | 게시 전 검토, 특정 상품 설명만 안전하게 업데이트 |

### 2.3 Job to Be Done

> 신상품 원본 사진을 확보했을 때, 별도 촬영·모델·디자인팀이 없어도 신뢰할 수 있는 판매용 이미지와 편집 가능한 상세페이지를 제작하고 내가 관리하는 스토어에 정확히 반영하고 싶다.

## 3. 목표 · 비목표 · 성공 지표

### 3.1 목표

- G1. 원본 이미지 업로드부터 모델 착용샷/단독컷/상세페이지 **첫 초안 생성**까지 연결된 플로우.
- G2. 판매자가 **제품 원형 보존 체크** 후 결과물을 승인하거나 부분 재생성.
- G3. 긴 상세페이지를 **구조화된 편집 문서**로 저장하여 나중에 다시 수정.
- G4. 카페24/스마트스토어와 분리된 공통 콘텐츠 도메인을 설계.
- G5. 초기 설계 용량은 **하루 약 100개 생성 이미지/워크스페이스** 수준을 기준으로 큐·예산·관측 체계 구성 (성능 보장 또는 구독 포함량 아님).

### 3.2 비목표 (초기)

- Photoshop/Figma 모든 디자인/협업 기능의 완전한 재현.
- 판매자 상품의 가격·재고·배송 정책 전체를 SELLAYER가 관리하는 ERP/PIM.
- AI 모델을 실존 인물로 가장하거나 타인의 얼굴을 무단 복제.
- 100% 동일한 제품 형태를 보증하는 완전 자동 무검수 발행.
- 네이버/카페24의 심사 승인 없이 외부 판매자 계정에 자동으로 접근.
- 상품 사진만으로 공식 성분·안전 인증·재질·치수를 추측하여 사실처럼 표기.

### 3.3 지표 (베타에서 기준선 수집 후 목표 확정)

| 지표 | 정의 | 단계별 목표 |
|---|---|---|
| North Star | 프로젝트 생성 7일 내 **승인된 상세페이지를 다운로드/게시**한 상품 수 | 베타 기준선 수집 |
| TTFD | 업로드 완료 → 첫 확인 가능한 초안 표시까지 경과 | p50/p95 실측, 최적화 |
| Fidelity pass | 블라인드/휴먼 검수 기준 상품 특징 불일치 없는 생성 컷 비율 | 카테고리별 기준선 → 개선 |
| Rework | 최초 컷당 재생성 횟수 | 1차 대비 감소 추세 |
| Editor completion | 편집기 진입자 중 저장/내보내기 완료율 | 베타 목표 TBD |
| Publish success | API 호출 성공 **및 대상 상품 반영 재조회 확인** 비율 | 목표 99% 이상(정상 플랫폼 가용 시) |
| Contribution margin | 구독/크레딧 실매출 - 모델/스토리지/플랫폼 변동비 | 양수 유지 목표 |

## 4. 사용자 여정 (Happy Path)

1. **가입/로그인 → 워크스페이스 생성**: 브랜드명, 톤/무드, 기본 설정 선택.
2. **상품 프로젝트 생성**: 상품명, 카테고리, 옵션/색상, 검증된 제품 스펙 입력.
3. **원본 업로드**: 정면·측면·클로즈업 사진과 선택적 레퍼런스 무드 사진 지정.
4. **특징 확인**: AI가 추출한 형태·색상·소재·장식·클라스프/단추 위치 등을 판매자가 확인/수정.
5. **촬영 패키지 구성**: 모델 착용샷 / 단독샷 / 디테일샷 / 라이프스타일샷 종류, 비율, 수량, 품질 선택.
6. **비용 확인 → 생성**: 예상 크레딧과 사용량 한도 표시. 비동기 큐에 등록.
7. **갤러리 리뷰**: 비교 미리보기, 불일치 표시, 승인/거절/재생성, 원하는 컷 선별.
8. **상세페이지 초안 생성**: 이미지와 확인된 정보로 가변 블록 문서 구성.
9. **웹 편집**: 텍스트·이미지·섹션·레이어·레이아웃 수정, 자동 저장/버전 복구.
10. **채널별 게시/내보내기**: 미리보기 및 명시적 승인 후 카페24/네이버 업데이트 또는 ZIP/PNG/HTML 다운로드.
11. **사후 수정**: 원본 문서를 계속 보유하며 변경점 비교 후 해당 채널에 재반영.

### 4.1 예외 흐름

- 입력 사진 부족 → 권장 추가 앵글 안내; 작업은 제한 모드로 진행 가능.
- 사실 정보 누락 → 에디터에서 `정보 미확인`으로 표시하고 외부 게시 전 수동 채움.
- 제품 동일성 경고 → 해당 자산 게시 후보에서 제외, 재생성 또는 원본 사용.
- AI 공급자 오류/쿼터 초과 → 지수 백오프, 명확한 에러, 부분 성공 자산 유지.
- 플랫폼 인증 만료/권한 부족 → 재연결 유도, 기존 작성 문서 보존, 조용한 재시도 금지.
- 게시 실패 → 기존 채널 상품 보존 여부 확인, 실패 범위·복구 방법 안내.

## 5. 범위와 우선순위

| Stage | 내용 | 출시 관문 |
|---|---|---|
| **M0: Private Alpha** | 로그인, 상품·원본 관리, 이미지 생성 4종, 리뷰/재생성, 상세페이지 JSON 블록 편집기, PNG/JPG/ZIP 출력, 작업·비용 대시보드 | 실제 상품으로 Fidelity/저장복구 검증 |
| **M1: Public Beta** | 상세페이지 템플릿, 브랜드 프리셋, 카페24 계정 연결 및 **기존 상품 콘텐츠 업데이트**, 공개 과금/크레딧, 감사 로그 | 카페24 연동/스토어 심사 및 이용약관 검증 |
| **M2: Channel Expansion** | 네이버 커머스솔루션마켓 등록·승인, 스마트스토어 **기존 상품 콘텐츠 업데이트**, 채널별 렌더링, 멀티채널 상태 추적 | 네이버 승인·실스토어 검증 |
| **M3: Scale** | 100장+ 배치 경험 개선, 모델/브랜드 일관성, 복수 사용자, 템플릿 마켓, 고급 레이어, 신규 상품 등록/추가 플랫폼 | 수익성·보안·성능 관문 |

**단계 의존성:** 외부 채널 연동이 지연되어도 독립 SaaS의 이미지 생성/편집/다운로드는 제공 가능해야 한다. 네이버 연동을 M0 완료 조건으로 묶지 않는다.

## 6. 상세 기능 요구사항

각 FR 항목은 개발 티켓, 테스트 케이스와 1:1 이상 연결해야 한다.

### 6.1 계정, 워크스페이스, 프로젝트

- **FR-001 MUST**: 이메일/안전한 인증 수단으로 가입·로그인·로그아웃·비밀번호 재설정. 임의 사용자/워크스페이스 접근 금지.
- **FR-002 MUST**: 1인당 하나 이상 워크스페이스; 프로젝트는 소유 워크스페이스에 귀속, 생성·복제·보관·삭제 가능.
- **FR-003 MUST**: 프로젝트에 상품명, SKU(선택), 카테고리, 판매 채널, 옵션(색상/사이즈), 확정 상품 스펙 저장.
- **FR-004 SHOULD**: 브랜드 프리셋 (폰트/색상, 사진 스타일, 얼굴 노출 정책, 모델 프로필, 금지 요소).
- **FR-005 MUST**: 모든 파생 결과물은 원본과 프로젝트 관계, 작업 ID, 출처, 생성 시각을 추적 가능.

### 6.2 원본 업로드와 상품 특징 고정

- **FR-010 MUST**: JPG/PNG/WebP 여러 장 업로드, 드래그앤드롭, 정렬·대표사진 지정, 촬영 앵글 지정.
- **FR-011 MUST**: 원본은 **불변 자산**으로 보관. AI 출력이 원본 파일을 덮어쓰지 못하게 하고 체크섬을 저장.
- **FR-012 MUST**: AI가 추출한 특징(카테고리/실루엣/색상/금속 색상/스톤 개수·형태/체인 타입/잠금장치·단추 위치/크기)을 사용자가 확인·수정·잠금.
- **FR-013 MUST**: 수치·재질·원산지·인증·효능/성능 등 **검증되지 않은 문구는 자동 확정 금지**. 값의 출처를 `seller_verified | imported_verified | inferred_unverified`로 관리.
- **FR-014 SHOULD**: 누끼, 배경 제거, 리사이즈, 크롭, 색상 보정. 각 작업 후 원본과 비교 가능.
- **FR-015 MUST**: 업로드한 상품/인물 사진의 사용 권리 확인 및 신고·삭제 흐름. 이미지에 포함된 개인정보·메타데이터 처리 정책 정의.

### 6.3 이미지 생성 엔진

- **FR-020 MUST**: 생성 유형 `MODEL_WEAR`, `PRODUCT_SOLO`, `DETAIL`, `LIFESTYLE` 네 가지.
- **FR-021 MUST**: 실물 제품 이미지 기반 **편집/참조 이미지 입력**을 우선 사용하며, 기존 상품을 다른 제품으로 재창작하지 않도록 고정 특징을 프롬프트에 포함.
- **FR-022 MUST**: 모델 성별/성인 연령대/피부톤/헤어/메이크업/옷 스타일/배경/조명/화각/카메라 느낌/얼굴 노출 여부 선택.
- **FR-023 MUST**: 카테고리별 착용 위치 기본값(귀걸이=귓불, 반지=손가락, 팔찌=손목, 목걸이=목·쇄골); 화면상의 과도한 크기 왜곡 검수 지원.
- **FR-024 MUST**: 1회 생성 패키지/수량/화면비(1:1, 4:5, 9:16 및 지원하는 사용자 규격)/품질을 선택하고 예상 소모량 확인.
- **FR-025 MUST**: 생성 작업의 `QUEUED → RUNNING → SUCCEEDED | FAILED | CANCELLED` 상태 표시. 부분 성공이면 성공 결과 즉시 이용 가능.
- **FR-026 MUST**: 자산 단위 승인·거절·재생성. 재생성 시 원본·고정 특징·실패 이유를 유지하고 버전 번호 증가.
- **FR-027 MUST**: 생성 이미지에 `AI-generated`, 모델/버전, 비용/사용량, 원본 참조, 프롬프트 버전, 생성 작업 ID를 내부 메타데이터로 보관.
- **FR-028 SHOULD**: 같은 브랜드 모델·의상·배경·톤 프리셋을 여러 상품에 재사용(완벽한 인물/자세 일치 보장 아님).
- **FR-029 SHOULD**: 자동 품질 경고(제품 형태 변형, 보석/단추 개수·위치, 브랜드 로고, 모델 해부학적 오류, 텍스트/워터마크 등) 및 비교 보기.
- **FR-030 MUST**: 승인되지 않은 결과물을 게시 작업에 기본 포함하지 않음.
- **FR-031 MUST**: 실존 인물 얼굴은 적법한 사용 동의 확인, 타인 사칭 금지. 가상 모델 이미지를 실제 착용 검증/실촬영 증거라고 허위 표현하지 않음.

### 6.4 이미지 갤러리 · 배치

- **FR-040 MUST**: 원본 / 생성 / 승인 / 거절 / 사용됨 필터, 태그, 검색, 정렬.
- **FR-041 MUST**: 같은 상품에 여러 생성 요청을 큐잉. 요청 고유키 기반 중복 생성·이중 과금 방지.
- **FR-042 MUST**: 사용자가 확인 가능한 일/월 크레딧 및 **금액/수량 상한** 제공. 상한 초과 시 실행 전 차단.
- **FR-043 MUST**: 작업별 시도 횟수·실패 이유·원가·과금 상태 기록; 실패 시 정책 기반 환불/복구.
- **FR-044 SHOULD**: 하루 약 100장 생성 요청을 받는 배치 UI와 진행률. 실제 처리 속도는 외부 모델의 레이트리밋/가용성에 종속.
- **FR-045 SHOULD**: ZIP 일괄 다운로드, 결과물 파일명 규칙(브랜드/상품/유형/버전), 중복명 자동 처리.
- **FR-046 MUST**: 실패/재시작 이후에도 DB 기반 작업 상태 복원, 워커 멱등성 보장.

### 6.5 상세페이지 자동 구성

- **FR-050 MUST**: 상품 정보와 **승인된 이미지**만을 이용해 상세페이지 초안 생성.
- **FR-051 MUST**: 가변 블록 구조: `Hero`, `Image`, `Text`, `FeatureGrid`, `ImageText`, `SpecTable`, `SizeGuide`, `CareGuide`, `Notice`, `Divider`, `CTA`.
- **FR-052 MUST**: 카테고리별 템플릿: 주얼리 기본 템플릿부터 시작, 이후 패션/뷰티 확장.
- **FR-053 MUST**: 상세페이지 카피는 검증된 사실만 사용. 없는 정보를 AI가 창작하면 `검토 필요` 상태로 게시 차단.
- **FR-054 MUST**: 문서 원본을 **편집 가능한 구조화 JSON**으로 저장. 출력 이미지/HTML은 파생물이며 원본이 아님.
- **FR-055 MUST**: 미리보기 폭/출력 해상도 및 섹션별 비율 조정. 글자 잘림·저해상도 이미지 경고.
- **FR-056 SHOULD**: 동일 상품의 카페24/네이버 표시 차이별 렌더러 및 채널별 미리보기.

### 6.6 비주얼 편집기 (Figma-like, MVP는 Lite)

- **FR-060 MUST**: 캔버스(중앙), 레이어/섹션 탐색(좌), 속성 패널(우), 툴바/미리보기 제공.
- **FR-061 MUST**: 텍스트 클릭 편집, 폰트/크기/색상/줄간격/정렬/굵기 수정.
- **FR-062 MUST**: 이미지 바꾸기/크롭/위치/크기/비율 편집, 블록 추가·복제·삭제·정렬.
- **FR-063 MUST**: 블록/레이어 드래그 및 순서 변경, 섹션 잠금, 줌과 기본 가이드.
- **FR-064 MUST**: Undo/Redo, 자동 저장(디바운스), `저장 중/저장됨/저장 실패` 상태, 새로고침 후 복원.
- **FR-065 MUST**: 초안/게시 버전 및 이전 버전 복구, 게시본과 수정본 구분.
- **FR-066 MUST**: 브라우저 미리보기와 내보낸 결과에서 **문구/이미지/블록 순서 일관성** 유지.
- **FR-067 SHOULD**: 템플릿 커스터마이즈, 브랜드 프리셋/스타일 토큰, 요소 간 정렬 가이드.
- **FR-068 MAY**: 임의 자유형 벡터 편집, 실시간 공동편집, 플러그인/컴포넌트 마켓은 M3 이후.
- **UX 원칙**: 상세페이지 긴 세로형 문서를 주 경험으로 제공. 완전 자유 캔버스보다 **구조화 블록 + 제한된 절대 위치 편집**부터 시작해 출력 안정성 확보.

### 6.7 내보내기 / 게시 / 플랫폼

- **FR-070 MUST**: JPG/PNG, 세로 상세페이지 PNG(필요 시 분할), ZIP 일괄 내려받기.

- **FR-075 MUST**: 요청·응답·대상 ID·시각·해시·승인자·이전 버전(가능 범위)·후속 조회 결과를 감사 로그로 저장.
- **FR-076 MUST**: 게시 부분 실패 및 API rate limit을 구분해 보여주고, 재시도 시 멱등성/중복게시 방지.
- **FR-077 MUST**: Cafe24 연결과 Naver 연결을 **별도 커넥터**로 구현; 고객별 권한 격리, 보안 저장.
- **FR-078 SHOULD**: 채널별 최소 유효 서식/이미지 규격 검사, 스토어별 템플릿 렌더링 및 결과 스냅샷 저장.
- **FR-079 MAY**: 신규 상품 등록, 가격/재고 수정, 다수 상품 벌크 게시, 다른 채널 확장(M3).
- **중요:** 카페24 앱스토어 및 네이버 커머스솔루션마켓 사용·API 접근은 **사업자/앱 심사·권한 부여 등 외부 의존성**이 있으므로 승인 전 사용 가능하다고 판매하지 않는다. 세부 사항은 [채널 연동](./CHANNEL_INTEGRATIONS.md).

### 7.1 핵심 UX 원칙

- **먼저 미리보기, 나중에 과금/게시.** 비용/외부 변경이 일어나는 버튼은 명확히 구분.
- AI 생성 결과는 기본적으로 후보 자산이며 **사용자가 승인한 것만 발행**.
- 상품 특징 Lock(변경 금지)와 Style(변경 가능)을 별도 제어.
- 모바일에서는 갤러리/승인/가벼운 텍스트 수정 중심; 정밀 편집은 데스크톱 우선.
- 한국어 UI 우선, 데이터/템플릿 구조는 다국어 대응.
- 중요한 작업마다 상태/재시도/취소/이전 버전 복구 방법 제공.

## 8. 데이터 개념 모델 (논리 모델)

- `User`, `Workspace`, `Membership`, `BrandPreset`
- `ProductProject`, `ProductVariant`, `VerifiedProductFact`, `ProductFeatureLock`
- `Asset` (`ORIGINAL`, `REFERENCE`, `GENERATED`, `EXPORT`), `AssetReview`
- `GenerationBatch`, `GenerationJob`, `GenerationAttempt`, `ProviderUsage`
- `PDPDocument`, `PDPRevision`, `PDPBlock` (JSON), `Template`
- `ChannelConnection`, `ChannelProductLink`, `PublishAttempt`, `PublishSnapshot`
- `Subscription`, `CreditLedger`, `Invoice`, `AuditEvent`

**데이터 불변식**

1. 모든 자산/작업/문서는 반드시 `workspaceId`로 분리된다.
2. `originalAssetId`는 생성 이미지보다 먼저 존재하며 원본을 덮어쓰지 않는다.
3. 제품 검증 사실, AI 추론 사실, 사용자 작성 문구를 구분한다.
4. `PDPRevision`은 편집기의 단일 진실 공급원(SoT); 게시/출력은 revision hash를 참조한다.
5. 채널 매핑 키는 `platform + connectedAccountId + externalProductId` 복합 식별자.
6. 결제/사용량 기록은 누적 변경 대신 정산 가능한 **추가형 ledger**로 보관한다.

### 9.1 안전한 파일/콘텐츠 취급

- 업로드 파일 타입·확장자·실제 MIME·사이즈 검사; 악성 콘텐츠/이미지 파서 취약점 방어.
- 사용자가 올린 텍스트/이미지 속 프롬프트를 시스템 명령으로 취급하지 않음(프롬프트 인젝션 격리).
- 외부 HTML은 allowlist 기반 정화, 스크립트 실행 금지.
- 고객 스토어 OAuth/서명 비밀은 로그/브라우저/저장소에 노출 금지.
- 원본 상품에 포함된 로고/이미지의 적법한 사용 권한과 생성물 상업 이용 조건을 확인.
- AI 모델컷의 가상 모델임을 내부적으로 추적하고 소비자 오인 가능성 및 채널 정책 확인.

## 10. 기준 기술 방향 (Architecture Guardrails)

**구현 전 검증할 후보**이며, 채택 확정된 기술 목록은 아님.

- 웹/앱: Next.js + React + TypeScript, Tailwind / component primitives.
- 에디터: Block-based document renderer + Fabric.js/Konva 등 캔버스 계층 PoC; 브라우저 편집과 출력 동일성 우선.
- 서버: Node.js API/worker, PostgreSQL, Redis/BullMQ와 멱등 키.
- 저장소: S3 호환 객체 스토리지(원본/생성/썸네일/내보내기 분리). 파일 접근은 서명 URL 또는 접근 제어.
- AI: 벤더 교체 가능한 `ImageGenerationProvider`, `TextGenerationProvider`, `QAProvider` 인터페이스; API 기반 요금 측정.
- 모델 선택: 출시 시점 화질/제품 보존/가격/지연 테스트를 통해 확정. 특정 모델명에 PRD가 종속되지 않음.
- 배포: Hostinger VPS Ubuntu 24.04 + Docker Compose + GitHub Actions + HTTPS + 마이그레이션/롤백.
- 보안: 외부 배포용 SSH 권한/환경변수는 GitHub Actions Secrets 또는 서버 시크릿 저장소에만 보관.

**주의:** ChatGPT Pro 구독량을 자체 SaaS 고객에게 무제한 이미지 생성 API처럼 재판매/전용하는 구조를 전제로 하지 않는다. 서버측 이미지 공급자 API와 별도 과금/한도를 사용하며, 개발자의 Codex 구독 사용은 개발·검증 용도로만 취급한다.

## 11. 출시 승인 기준 / 인수 조건

### M0 Private Alpha (필수)

- **AC-01** 신규 사용자가 로그인하여 본인 워크스페이스에서 상품 프로젝트를 생성한다.
- **AC-02** 원본 이미지 3장을 업로드해도 원본 SHA가 유지되고 생성물은 신규 Asset으로 저장된다.
- **AC-03** 주얼리 상품 잠금 특징(색상, 스톤 배열, 잠금장치)을 수정·잠금하고 생성 요청에 반영한다.
- **AC-04** 제품 단독/모델 착용/디테일/라이프스타일 중 원하는 컷 종류와 개수를 선택한다.
- **AC-05** 생성 요청 전 예상 사용량 확인; 예산 제한을 넘으면 생성이 시작되지 않는다.
- **AC-06** 생성 4건 중 1건 실패해도 성공 3건은 갤러리와 상세페이지에서 이용할 수 있다.
- **AC-07** 리뷰에서 승인하지 않은 컷은 상세페이지 자동 선택 대상에서 제외된다.
- **AC-08** AI가 추론한 미확인 상품 치수/재질은 사실로 게시할 수 없다.
- **AC-09** 상품 이미지와 승인 정보를 반영해 편집 가능한 상세페이지 JSON이 만들어진다.
- **AC-10** 텍스트·이미지 교체·섹션 순서 수정 후 자동저장·새로고침·Undo/Redo·버전 복구가 동작한다.
- **AC-11** 저장한 버전과 PNG/ZIP 내보내기의 이미지·문구·블록 순서가 일치한다.
- **AC-12** 다른 사용자/워크스페이스의 이미지와 PDP 문서에 접근 시 거부된다.
- **AC-13** 이미지 생성 실패/서버 재시작/중복 이벤트에 대해 상태와 과금이 일관된다.

### M1 Cafe24 Beta (추가)

- **AC-14** 승인된 Cafe24 OAuth로 특정 쇼핑몰을 연결/해제하고 대상 상품 조회에 성공한다.
- **AC-15** 게시 전 변경 범위와 미리보기를 확인한 뒤 *상세페이지/선택한 이미지 필드만* 업데이트한다.
- **AC-16** 테스트 상품의 가격·재고·옵션·배송 정책은 연동 전후 불변임을 검증한다.
- **AC-17** 실패 시 원인·범위·이전 스냅샷이 기록되고 재시도 또는 가능한 복원 절차가 제공된다.

### M2 Naver Beta (추가)

- **AC-18** 승인받은 솔루션·판매자 인증 플로우에서만 스마트스토어 상품에 접근한다.
- **AC-19** 채널 규격에 맞춰 렌더링 후 명시적으로 승인된 기존 상품 설명/이미지 필드만 갱신한다.
- **AC-20** 판매자/스토어별 토큰·상품 ID·실행 로그가 혼합되지 않는다.
