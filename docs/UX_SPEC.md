> **문서 ID:** SL-UX-001 · **버전:** v0.1 · **작성일:** 2026-10-16 (KST)

> **연계:** [PRD](./PRD.md) · [기술설계](./TECHNICAL_DESIGN.md) · [품질 계획](./QUALITY_PLAN.md)

## 0. 목표 사용자 경험

SELLAYER의 핵심 UX는 다음 네 가지다.

1. **Upload:** 판매자가 실물 상품 원본 1~10장과 특징을 지정.
2. **Generate:** 제품은 유지하고 모델·배경·촬영 방식만 바꾼 AI 이미지 생성.
3. **Review & Design:** 결과를 원본과 비교·승인하고 수정 가능한 상세페이지를 제작.
4. **Publish:** 채널별 프리뷰를 확인하고 카페24/네이버에 안전하게 반영하거나 파일 다운로드.

**중요**: "피그마처럼 편집"은 데스크톱 웹에서 **캔버스 + 레이어 목록 + 우측 속성 패널 + 직접 조작 + 버전관리**를 제공한다는 의미다. 포토샵/Figma 모든 기능을 복제한다는 뜻이 아니다. M0은 **세로 상세페이지 전용 블록 편집 + 블록 내 제한적인 자유 배치**로 고정한다.

## 3. 온보딩부터 첫 상세페이지까지

### 3.1 권장 최소 입력

**프로젝트 생성:** 상품명(필수) + 카테고리(필수) + 원본(필수). 색상/옵션/모델 참조는 진행 중 언제든 추가 가능. 사용자가 사실 값을 제공하지 않았을 때 임의의 가짜 소재/가격이 자동으로 들어가지 않는다.

처음부터 폼이 너무 길어지지 않도록 3단계 안내:
1. "상품 원본 업로드" — 이미지 1장만으로 시작 가능, **다각도 3장 이상을 권장**.
2. "상품을 그대로 유지할 특징 확인" — 위치·색상·장식·형태 등 상품 정보 검수.
3. "원하는 컷 만들기" — 모델/컷 프리셋 선택 및 견적 확인.

### 3.2 이미지 업로드 UX

- Drag & Drop 또는 파일 선택, 업로드 큐에 파일별 진행률·에러.
- 원본 썸네일에 FRONT / SIDE / DETAIL / BACK / VARIANT / STYLE_REF 태그.
- **PRODUCT_REFERENCE와 STYLE_REFERENCE를 시각적으로 분리**. 스타일 참조가 상품 자체로 사용되는 실수를 방지.
- 색상 옵션이 여러 개면 Variant 칩을 생성하고 원본을 색상별로 묶음.
- 파일 제거 시 연관된 feature lock/초안 생성의 영향을 알려주고 사용자 확인.
- 원본과 생성본이 혼동되지 않도록 파란색 등 강조 배지 대신 문자 라벨 **원본** / **AI 결과** 사용.
- 원본 이미지 메타(EXIF 위치 포함) 처리 안내 링크와 사용 권리 확인 체크.

### 3.3 상품 특징 Lock 화면

~~~text
┌────────────────────────────────────────────────────────────────────┐
│ 상품 특징 확인                                    [저장] [다음 →] │
├────────────────────────────────┬───────────────────────────────────┤
│                                │ AI가 추정한 특징 (검토 전)         │
│   [원본 전면 이미지]             │ 제품 형태   원형 후프        [잠금]│
│                                │ 금속 색상   실버             [잠금]│
│   [측면] [디테일] [컬러옵션]     │ 잠금 구조   힌지             [잠금]│
│                                │ 스톤 개수   확인 필요        [편집]│
│   ▲ 확대해서 디테일 확인       │ 사이즈       사용자 확인     [입력]│
└────────────────────────────────┴───────────────────────────────────┘
  AI 추정은 사실이 아닙니다. 정확한 제품 정보를 확인해주세요.
~~~

Lock의 의미:
- **Critical:** 반드시 유지해야 하는 구조(잠금장치 종류, 스톤 배열, 컬러, 패턴, 단추/장식 위치).
- **Major:** 가급적 유지(반사감, 표면 마감, 실측 비율).
- **Style:** 변경 가능(배경/모델/의상/조명).

UI는 lock이 "AI가 반드시 성공한다"는 보증처럼 보여서는 안 된다. 도움말: **"상품 특징을 생성 지침과 검수에 반영합니다. 결과는 직접 확인해 주세요."**

## 4. AI 스튜디오 화면

### 4.1 기본 구성

~~~text
┌──────────────────────────────────────────────────────────────────────────┐
│ AI 스튜디오                               크레딧 2,450  [생성 기록]     │
├──────────────────────┬────────────────────────────────┬──────────────────┤
│ 상품 옵션            │ 촬영 패키지                     │ 예상 사용량       │
│ ○ 실버 ○ 골드         │ [착용샷 4] [단독 4]             │ 총 10장           │
│ 원본 3장 연결됨      │ [디테일 2] [라이프스타일 0]      │ 약 000 크레딧     │
│ 잠금 특징 5개        │                                │ 재생성 별도 안내 │
│                     │ 모델: 한국/글로벌 성인(가상)     │                  │
│ [원본 보기]          │ 얼굴 노출: 안 함                │ [변경 사항]      │
│                     │ 촬영: 아이폰 자연광/스튜디오     │ 상품 특징 5개    │
│                     │ 비율: 4:5 / 1:1 / 9:16          │ 참조 이미지 3장  │
│                     │ 품질: Low/Medium/High           │                  │
│                     │ [미리보기 프리셋]               │ [10장 생성하기]  │
└──────────────────────┴────────────────────────────────┴──────────────────┘
~~~

**사용자가 자주 수정할 항목**은 프리셋으로 상단에 배치:
- 상품 유형/색상 → 모델 착용샷 선택 시 착용 부위 자동 선택.
- 촬영 스타일: 자연광 아이폰 감성, 고급 스튜디오, 미니멀 라이프스타일, 브랜드 맞춤.
- 모델 설정: 얼굴 비노출(목 아래/손만 등), 성인 연령대, 피부톤·의상 무드.
- 보존 설정: 잠금 특징 표시, "제품 변형 위험 있음" 경고.
- 시안 개수와 출력 비율/화질이 비용에 영향을 주면 즉시 견적 재산정.

### 4.2 생성 버튼의 동작

1. 입력 validation → 검증 안 된 중요 정보 확인.
2. 예상 총 크레딧/잔액/일일 상한/실패 환불 정책 확인.
3. 모달에서 "이 설정으로 10장 생성" 확인.
4. 서버 quoteId/Idempotency-Key 요청 → 배치 ID 수신.
5. 완료 전에도 진행 페이지로 이동 가능. 브라우저 종료 후 다시 들어오면 서버 진행 상태 조회.

**금지:** 비용이 발생하는 액션을 단순 탭 이동/미리보기로 실수 실행하거나 버튼 다중 클릭으로 이중 청구하지 않음.

### 4.3 배치 100장 UX

- 처음에는 batch 당 수량 상한을 공급자 속도·예산에 맞춰 제한. "100장 요청"은 가능하더라도 여러 배치로 분리할 수 있음.
- 상단 진행: 총 100개 중 완료 68, 검토 필요 62, 실패 6 등 **합계 규칙** 명확히. 완료와 승인 건수는 구분.
- 행별 상태: 대기/생성 중/검토 필요/승인됨/실패/재생성 필요. 시간 예상치는 최근 실제 처리 데이터가 충분할 때만 표시.
- 부분 완료 시 먼저 생성된 이미지를 검토 가능.
- 실패 건만 다시 요청하는 버튼은 재생성 비용을 **미리 표시**.
- 일시중지 요청은 **아직 시작하지 않은 job의 dispatch 중단**, 이미 공급자에 전송된 작업을 중지한다는 의미가 아님.

## 5. 이미지 검토/갤러리

### 5.1 그리드 + 원본 비교

- 왼쪽 필터: 전체/원본/검토필요/승인/거절/상품컷/모델컷/색상.
- 중앙 격자: 이미지, 타입/색상/버전, 승인 상태, QA 경고 숫자, 생성 시각.
- 우측 상세 패널: 원본 vs 생성본 비교 슬라이더, 잠금 특징 체크, 모델 프리셋, 결과 이미지 메타, 승인/거절/재생성.
- 모바일은 비교 슬라이더와 승인 중심으로 최소 UI 제공; 3패널 편집은 데스크톱 중심.

### 5.2 비교 모드 인터랙션

~~~text
┌───────────────────────────────┬───────────────────────────────────┐
│       ORIGINAL                │            AI RESULT              │
│   [실물 디테일 사진]           │         [모델 착용 결과]           │
├───────────────────────────────┴───────────────────────────────────┤
│ 검수 체크                                                           │
│ [✓] 금속 색상 유지    [!] 잠금장치 형태 확인 필요    [✓] 스톤 배열   │
│ [거절] [재생성 요청]                     [승인하고 상세페이지에 사용]│
└───────────────────────────────────────────────────────────────────┘
~~~

- **승인**은 명시적 사용자 행위이며 QA PASS가 자동 승인으로 전환되지 않음.
- **거절 사유**: 상품 형태 변경, 스톤 수/배열 오류, 색상 오류, 착용 위치 오류, 모델 비현실적, 기타.
- 재생성 요청 UX: "그대로 유지할 것"과 "이번에 바꿀 것" 두 입력 상자로 구분; 가능하면 관련 부분 표시.
- 한 상품의 골드/실버 이미지를 혼합하는 사고를 막기 위해 색상 옵션을 선택/잠금.
- 모델 비노출 정책(목 아래, 손/귀만)의 위반은 검토 경고와 재생성 제안.

## 6. 상세페이지 템플릿 선택

- 기본 템플릿: **미니멀 럭셔리 주얼리**. 후속: 캐주얼 패션, 뷰티, 라이프스타일.
- 카드 미리보기에는 실제 선택된 상품 승인컷이 삽입되고 텍스트는 검증된 상품 사실을 사용.
- 기본 섹션: Hero → 제품 특징 → 모델 착용 → 상세 제품컷 → 사이즈/소재 → 관리 방법 → 구매 공지.
- 사용자는 섹션을 체크해서 포함/제외할 수 있다.
- "AI가 제안한 카피"는 편집 가능하며 추론 사실이 들어간 구간에 **확인 필요** 표시.
- 승인된 상품 이미지가 0장일 때는 초안 생성이 차단되고 원본 사용/승인 단계로 돌아가게 한다.
- 특정 이미지가 없는 경우 나머지 이미지로 만들 수 있는 템플릿만 활성화.

### 7.2 패널별 컴포넌트

**상단 바**
- 뒤로 가기(저장 중 경고), 프로젝트명, 문서명 편집, 저장 상태.
- Undo/Redo (비활성 상태 명확히), 리비전 히스토리, 미리보기/다운로드.
- 원본/현재 상태 표시: 초안, 변경 있음, 저장 중, 저장됨, 저장 실패.
- 외부 게시 버튼은 출력 버튼과 시각적/의미적으로 분리하고 채널 연결 전에는 disabled 및 이유 표시.

**좌측 패널 (탭)**
- Layers: 섹션 트리 / 블록 트리, 드래그 핸들, hover / 선택 / 숨김 / 잠금 / 복제.
- Assets: 원본/승인된 AI 이미지/업로드/최근 사용 필터, drag to canvas.
- Sections/Templates: 섹션 프리셋 삽입, 썸네일로 배치 미리보기.
- 이곳에서 섹션 순서를 변경할 때 캔버스 위치도 실시간으로 변경.

**중앙 캔버스**
- 기본 A4가 아니라 스마트스토어/카페24의 **긴 모바일 상세페이지 미리보기**.
- 선택 상태: 파란 outline과 핸들/도구 팝오버. 실제 export에는 핸들 미출력.
- 하나 선택/다중 선택(다중 선택은 M1에서 확장 가능), resize/crop/drag, zoom/pan.
- 섹션 경계 가이드, 스냅, safe area, 페이지 전체 길이 표시.
- 텍스트 두 번 클릭 편집, 입력 중 다른 곳 클릭 시 편집 확정 또는 경고.
- 이미지 비율 고정 기본값, Fit/Fill 토글, 원본 확장으로 디테일 확인 가능.
- 렌더 중 자산 미로드 시 회색 placeholder 표시하되 export는 실패 또는 원본 참조 해결 후 진행.

**우측 속성**
- 아무 것도 선택 안 됨: 전체 페이지 너비, 배경, 테마, 브랜드 프리셋.
- Section 선택: 여백, 간격, 배경, 최대 너비, 수직 정렬.
- Text 선택: 문자, 글꼴, 크기, 굵기, 자간, 줄간격, 컬러, 정렬, 링크(허용 범위).
- Image 선택: 참조 asset, crop, contain/cover, 너비/높이, border radius, alt, 비율 잠금, 교체/재생성.
- SpecTable 선택: 표 행/열, 항목 출처, 누락 사실 강조.
- 생성 자산 선택: "AI 재생성"은 해당 asset의 새로운 버전을 만들고 **현재 페이지 교체 여부를 별도 확인**.

### 7.3 노드 선택 및 편집 규칙

| 이벤트 | 기대 동작 | 예외 |
|---|---|---|
| 텍스트 한 번 클릭 | 노드 선택 + 외곽선 | 텍스트 입력 모드 아님 |
| 텍스트 더블 클릭 | 커서 표시·텍스트 편집 | locked node 수정 불가 |
| 이미지 한 번 클릭 | 이미지 속성 표시 | 다운로드/원본 비교는 별도 버튼 |
| 이미지 교체 | Asset picker에서 approved 선택 | 미승인 이미지는 선택 비활성화 |
| 패널에서 drag | drop zone 강조 후 노드 이동 | 허용 안 되는 부모에 drop 거부 |
| node 복제 | 새로운 UUID 부여, 같은 Asset 참조 | 원본 이미지 바이트 복사하지 않음 |
| node 삭제 | undo stack에 복구 스냅샷 | 잠금 섹션은 우선 잠금 해제 |
| Ctrl/Cmd+Z | 직전 편집 명령만 되돌림 | 폼 입력 중 browser undo 우선 고려 |
| 새로고침 | 최근 서버 revision 로드 | unsaved changes 복구 prompt |
| 서버 409 | 편집 중지·충돌 다이얼로그 | 임의 덮어쓰기/데이터 손실 금지 |

### 7.4 편집기 상태 모델

~~~mermaid
stateDiagram-v2
  [*] --> LOADING
  LOADING --> READY
  READY --> DIRTY: edit
  DIRTY --> SAVING: debounce / explicit save
  SAVING --> READY: save success
  SAVING --> ERROR: network failure
  SAVING --> CONFLICT: revision conflict
  ERROR --> SAVING: retry
  CONFLICT --> READY: reload
  CONFLICT --> DIRTY: resolve / copy changes
  READY --> PREVIEW: preview
  PREVIEW --> READY: close preview
~~~

- **Undo/Redo stack**은 자동 저장 완료와 별개. 서버 revision 변경이 로컬 undo stack과 모순되지 않도록 snapshot boundary 정책 구현.
- 저장 재시도 중 작성 중인 내용을 잃지 않도록 로컬 임시 보존(브라우저 메모리, 필요시 IndexedDB를 별도 보안 평가 후).
- 창 닫기 / 경로 이동 시 미저장 변경이 남은 경우 확인.
- 큰 이미지가 많아도 편집 responsiveness를 유지하도록 viewport virtualization/lazy-loading.
- 출력을 위한 가시성은 편집 모드와 분리, print/export renderer에 도구 chrome/selection overlay 제외.

| 조작 | Windows/Linux | macOS | 설명 |
|---|---|---|---|
| Undo | Ctrl+Z | Cmd+Z | 최근 작업 취소 |
| Redo | Ctrl+Shift+Z | Cmd+Shift+Z | 최근 작업 복구 |
| Duplicate | Ctrl+D | Cmd+D | 선택 노드 복제 (브라우저 북마크 충돌 검토) |

## 10. 내보내기 UX

### 10.1 다운로드 마법사

1. 결과 선택: 개별 컷, 전체 승인 컷 ZIP, 상세페이지 전체, 섹션별.
2. 출력 규격: PNG/JPG, 긴 상세페이지(너무 길면 자동 분할), 추가 PDF/HTML 옵션은 지원 준비 이후 표시.
3. 사전 검증: 낮은 해상도, 미승인 이미지 참조, 검증되지 않은 사실, 글자 overflow, 외부 URL 접근 실패.
4. 내보내기 요청 → 작업 ID → 진행률·완료 다운로드 링크.
5. 파일명: 브랜드_상품명_옵션_유형_리비전.ext, 특수 문자 제거.
6. 동일 문서를 다시 내보내도 **어떤 리비전**에서 제작했는지 다운로드 이력으로 확인.

### 10.2 긴 상세페이지

- 모바일 규격을 가정한 예: 860px 또는 채널 권장 폭 중 선택.
- 최대 PNG 높이 제한 도달 시 섹션 단위 분할과 ZIP을 권장.
- 고해상도 원본 대신 저해상도 썸네일이 출력될 위험 안내.
- 테스트: 디자인 캔버스의 텍스트 줄바꿈, 이미지 crop, 폰트, 배경, 간격이 출력과 동일.
- 다운로드 완료 후 사용자가 채널에 수동 업로드해도 되는 **독립 파일 기반** 경험 유지.

## 11. 채널 연결과 게시 UX

### 11.1 채널 관리

~~~text
연결된 판매 채널
[카페24]     연결됨  | mall_id=***shop  [상품 가져오기] [연결 해제]
[스마트스토어]  출시 준비 중 (공식 연동 승인 필요)
[파일로 내보내기]  언제든 사용 가능
~~~

- 지원하지 않는 채널에 "곧 자동 게시됨"처럼 확정적으로 약속하지 않음.
- 연결 토큰의 권한 범위를 판매자가 볼 수 있게 표시.
- 실제 쇼핑몰이 2개 이상이면 target shop과 channel이 명시적으로 구분.
- 스토어 연결은 OWNER/ADMIN만 허용. 인증 실패/권한 만료 시 편집·다운로드는 계속 가능.

### 11.2 채널 게시 검토 모달

~~~text
카페24 상품 상세 설명 업데이트
스토어: example.cafe24.com
상품: 925 실버 테니스 팔찌 / 외부상품ID: 12345
대상 문서: Revision 7 (2026-10-16)
──────────────────────────────────────────
현재 상세 설명   →   SELLAYER 변경 후 미리보기
[Before snapshot]     [After preview]
변경되는 항목:
 ✓ 상세 설명 HTML
 ✓ 상세 설명 내 이미지 8개
변경되지 않는 항목:
 ○ 가격  ○ 재고  ○ 옵션  ○ 배송/반품 정책
──────────────────────────────────────────
[취소]  [변경 내용 확인 후 게시]
~~~

- publish 버튼은 **2단계**: 미리보기 생성 → 사용자가 변경 필드 승인.
- 외부 상품이 방금 변경되었다면 **게시 중단하고 다시 미리보기** 요구.
- 성공 상태는 단순 API 200이 아니라 GET 검증 후 "게시 확인됨".
- 외부 채널의 비동기 반영/캐시 때문에 검증이 지연되면 "반영 확인 중"으로 별도 표시.
- 복구 요청은 서버에 저장된 이전 스냅샷을 보여주고 **원복도 사용자 승인**을 요구.

## 13. 반응형 기준

- 1440px 이상: 좌/중앙/우 3패널 동시 표시.
- 1120~1439px: 패널 폭 축소, 일부 속성 탭 통합.
- 768~1119px: 레이어/속성을 토글 drawer로 표시, 긴 페이지 손쉬운 미리보기 및 간단 수정.
- 767px 이하: 대시보드, 업로드, 생성, 갤러리 검토, 가벼운 텍스트 변경, 승인/다운로드 중심. **정밀 캔버스 드래그 편집은 데스크톱 권장**을 표시.
- 키보드 없는 모바일에서는 다중선택이나 세밀한 가이드 대신 단계형 설정 UX 우선.
- 높이가 낮은 브라우저에서 툴바/액션이 숨지 않도록 sticky header/scroll strategy.

## 15. UX 인수 테스트 (UX-AC)

| ID | 테스트 | 통과 조건 |
|---|---|---|
| UX-AC-01 | 한 상품에 실버/골드 옵션별 3장 업로드 | 옵션 이미지가 서로 섞이지 않음 |
| UX-AC-02 | 잠금 특성 변경 | 기존 생성 결과에 변경 후 재검수 필요 표시 |
| UX-AC-03 | 10장 생성 버튼 빠르게 3회 클릭 | 서버에 **동일한 작업 한 번** 생성되고 비용 한 번 예약 |
| UX-AC-04 | 모델컷 4장 중 1장 거절 | 상세페이지 자동 선택에서 해당 자산 제외 |
| UX-AC-05 | 이미지 부분 재생성 | 새 버전으로 생성, 기존 승인본/문서 변경은 확인 후 |
| UX-AC-06 | 레이어 패널에서 섹션 순서 변경 | 캔버스 순서·저장 JSON·출력 이미지가 일치 |
| UX-AC-07 | 텍스트 3개 수정 후 새로고침 | 서버 저장 완료 이후 3개 모두 복원 |
| UX-AC-08 | 두 탭에서 같은 문서 수정 | 저장 충돌/비교가 표시되고 조용한 덮어쓰기 없음 |
| UX-AC-09 | 게시본 선택 후 에디터 수정 | 게시된 revision은 바뀌지 않음 |
| UX-AC-10 | 긴 8개 섹션 Export | 누락·순서 뒤바뀜·글자 잘림 없이 PNG/ZIP |
| UX-AC-11 | 카페24 미리보기 후 외부 가격 변경 | 다시 확인 절차를 요구하고 가격을 덮어쓰지 않음 |
| UX-AC-12 | 생성 사용량 상한 초과 | 생성 접수 전 차단하고 왜 안 되는지 안내 |
| UX-AC-13 | 1개 이미지/참조 URL 실패 | 전체 성공으로 오인하지 않고 자산 수준 오류 표시 |
| UX-AC-14 | 키보드만 사용해 블록 선택/수정 | 주요 기능 접근 가능, 포커스 위치 명확 |
| UX-AC-15 | 100장 생성 배치에서 20장 성공 후 접속 종료 | 재접속 후 완료 20장/나머지 진행 상태가 보존됨 |
